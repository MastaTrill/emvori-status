Models and routing

Emvori does not train a public foundation model of its own. Production answers run through a managed provider path with automatic fallback when a provider is rate-limited, unauthorized, or down.

What is true today

  • Chat, Research, and Agent share a routed inference layer rather than a single hard-coded public model name.
  • Reasoning profile (Auto / Fast / Deep) changes how much work the workspace spends before answering. Deep on Free is preview-only.
  • Research answers only from fetched pages. If the index is thin, Emvori says so instead of inventing citations.
  • Specification questions should prefer RFC and MDN pages over generic protocol-registry indexes.
  • A local-model bridge exists for operators who point Emvori at a model they run themselves. That is opt-in, not the default public path.

What we will not claim

  • We will not publish a fake always-one-vendor badge. The live route can change when a provider fails.
  • We will not claim on-device-only inference for the public AppDeploy origin.
  • We will not claim zero hallucination or a secret frontier engine in the product UI.
  • Frontier evaluation endpoints in the private source tree are operator/quality surfaces, not a promise that every chat uses every research module.

Your control

Anonymous chat still sends the current prompt to the inference path. Sign-in does not change that. It only adds account-scoped memory, limits, and integrations. Keep secrets out of prompts.
